## 문제 내용

세 번째 PR은 기존 이슈 #53103을 직접 구현한 기능 PR입니다. 병렬 테스트에서 `console.log()`가 섞이거나 먼저 도착해 **어느 테스트의 로그인지 구분하기 어려운 문제**를 다뤘습니다. 이 이슈에는 Hardhat 쪽에서도 Mocha처럼 테스트 제목 아래에 해당 로그를 보여주고 싶다는 사용 사례가 올라와 있었습니다.

### 짧은 데모

```
변경 전  test:stdout "DB 연결됨" [???]
         test:dequeue first

변경 후  test:dequeue first
         test:stdout "DB 연결됨" [first · #1]
```

기존에는 로그가 어느 테스트 것인지 알 수 없었고 순서도 뒤집힐 수 있었습니다. 변경 후에는 테스트 정보가 함께 전달돼 리포터가 로그와 테스트를 연결할 수 있습니다.

## 해결 과정과 검증

구현은 global `console`이 쓰기 직전에 async context로 현재 test/suite를 찾고 `testId`와 이름을 붙여 기존 출력 이벤트로 보내는 방식입니다. 실행 중인 test/suite와 suite hook처럼 **주인을 확실히 알 수 있는 출력만 연결**하고, top-level·늦은 출력·direct stream은 기존 동작을 유지했습니다.

### 검증 과정

- **07.30~31** — 첫 구현을 다시 확인하면서 낡은 바이너리와 파이프 청크 때문에 테스트가 잘못 판정될 수 있는 문제를 잡았습니다.
- **08.06~08** — 최신 `main`으로 옮긴 뒤 `Object.freeze(console)`, `child-v8`, 소스 위치가 없는 테스트 같은 경계 조건을 추가로 확인했습니다.
- **08.09** — 최종 로컬 검증을 마친 뒤 PR #65147을 제출했고, 이후 GitHub CI도 모두 통과해 현재 리뷰를 기다리고 있습니다.
